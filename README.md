## 법적 점검 반영 (2026-10-26)

- **이름 입력 없음** — 분석에 쓰지 않는 정보라 받지 않는다(개인정보 최소 수집, 개인정보 보호법 제16조). 예전 화면이 보내도 `cleanInput` 이 버린다.
- **함수 지역 서울** — `vercel.json` `regions: ["icn1"]`. 전에는 미국 동부(iad1)에서 돌아 입력 전체가 국외로 나갔다. 구글 제미나이·Vision 으로 가는 대화·사진은 여전히 국외 이전 → 정식 처리방침에 적을 것(법 제28조의8).
- **생성형 AI 고지(AI기본법 제31조, 2026-01-22 시행)** — 사전 고지: 동의 단계(대화·사진을 고른 경우 `.ai-note`)와 첫 화면 바닥글. 결과물 표시: AI 가 쓴 신호·사실(`by: 'ai'` — 대화 분석·사진 관찰)에 'AI 생성' 표시, 리포트 안내줄(`.rp-ai`), 신고용 정리본 '· AI 생성'. 같은 사진 웹 검색(Vision)은 생성형 AI 가 아니라 표시하지 않는다.
- 점검 C:/tmp/datecheck-test/check1026.mjs (BASE·W).

## 오류 안내 원칙 (2026-10-26 오너: 모든 오류에 친절한 쉬운 설명과 안내)

- **화면** — 서버와 주고받는 곳은 모두 `api()`(public/app.js) 하나로. 인터넷 끊김·연결 실패·늦음(504)·너무 큼(413)·JSON 아닌 답·서버 오류를 쉬운 말로 바꾸고, 점검·리포트 열기·문의는 화면에 남는 안내 + '다시 시도'. 설정을 못 받으면 점검 창 대신 안내와 '다시 시도'.
- **입력** — '다음'이 안 눌리면 이유 한 줄(`next.why`). 사진이 아닌 파일·HEIC·너무 큰 사진 안내. 대화 글 2만 자 넘으면 미리 알림.
- **저장이 막힌 브라우저** — 시작은 그대로 되고, 리포트 위에 'PDF로 저장' 안내(`unsaved`).
- **조회 서버가 잠깐 응답하지 않음** — `busy()`(lib/sources.mjs) 로 '무엇을 못 했는지 + 지금 할 수 있는 일(공식 화면 버튼)'. 이런 칸만 남은 항목은 상태 `retry` → '다시 확인 필요', 리포트 '잠시 확인하지 못한 항목' 구역. 키가 없어 못 하는 `pending`(연동 준비 중)과 구분. 공공데이터·국세청 조회는 연결 오류·5xx 한 번 더, 302 는 따라가지 않고 두 번까지 다시.
- **AI 실패** — 캡처 글자 읽기·대화 분석·사진 관찰이 안 되면 무엇을 못 봤는지와 대신 할 일을 알림줄로. 대화 분석은 한 번 다시 묻고(함수 60초 안), 그래도 안 되면 대화 항목 3~7 은 '다시 확인 필요'(규칙으로 대신하지 않는다). 사진 웹 검색 결과는 그대로.
- **없는 주소** — public/404.html (Vercel 이 알아서, PC 서버도 같게).
- 점검: C:/tmp/datecheck-test/err/errors.mjs (BASE·W, 28가지), tests/fallback.test.mjs.

## SNS 계정·이름은 받지 않는다 (2026-10-26 오너)

- 이름과 SNS 계정은 특정한 사람을 가리키는 정보라 받지 않는다(사람 찾기로 보이지 않게, 개인정보 최소 수집). 예전 화면이 보내도 `cleanInput` 이 버린다.
- 링크 칸·대화에 섞인 SNS·유튜브·블로그 주소는 `isSnsUrl`(public/parse-input.js)로 걸러 확인하지 않는다. 화면은 링크 칸에 SNS 주소만 넣으면 이유를 알리고 다음을 막는다.
- 사진 웹 검색에서 SNS 계정 페이지는 주소·제목(이름·아이디가 들어 있음)을 보여 주지 않고 개수만 — 상대 본인 계정이면 사람 찾기가 된다. 사진 관찰 AI 는 남의 계정 아이디를 옮겨 적지 않는다(프롬프트 + 서버에서 @아이디 가림).
- 전화번호·계좌번호 네이버 버튼은 '"번호" 사기'로 — 번호만 검색하면 그 사람에 관한 글이 다 나온다.
- 회사 입력: (주)·㈜·주식회사·Co., Ltd. 와 '다녀요·에서 일해요·대표' 같은 뒷말을 떼고 찾는다(companyName). 이름 비교는 nameKey.

## 카톡 대화 내보내기 파일 (2026-10-26 오너)

- 대화 단계 탭 셋: 캡처 올리기 · **카톡 파일** · 글로 붙여넣기. 카톡 파일은 `public/kakao-export.js` 가 **브라우저 안에서** 읽어, 고른 사람은 '나:' 나머지는 '상대:' 줄로 바꾼 글(chatText)만 서버로 보낸다. 이름과 파일은 서버로 가지 않는다.
- 받는 모양: PC(윈도우) `[이름] [오후 3:21] 메시지` 와 날짜 구분선, 휴대폰 `2026년 10월 26일 오후 3:21, 이름 : 메시지`(아이폰은 점 날짜·24시간), 영어 판, 맥 CSV, 이 파일이 든 zip(사진까지 내보낸 경우, 나뉜 파일은 이름 순서로 이음). UTF-8·UTF-16·EUC-KR.
- '나' 정하기: 휴대폰 파일의 '회원님', 1:1 대화면 제목('○○ 님과 카카오톡 대화')의 반대편. 단체방·제목 없는 파일은 이용자가 고른다('이 중에 나는 없어요' = 모두 상대).
- 여러 줄 메시지는 한 줄로, 사진·이모티콘은 [사진]·[이모티콘], 들어옴·나감 안내 줄은 뺀다. 날이 바뀌는 곳에 [날짜] 줄(대화 보기의 날짜 띠).

- 글로 붙여넣기에 카톡 PC 에서 복사한 글을 넣으면 같은 바꾸기를 권한다.

- 복사 칸(`copyField`): 번호 + 복사 버튼, 누르면 2초간 '복사됨'. 클립보드가 막히면 번호를 선택해 둔다. 번호 글자에는 줄바꿈용 붙임 글자를 넣지 않는다(직접 끌어 복사해도 깨끗하게).
- 캡처: `public/img/howto/` — PC용 `police-phone·police-account·thecheat.webp`, 폰용(폭 600px 이하) `*-m.webp`, 크기는 `sizes.json`. 경찰민원24 폰용은 실제 모바일 화면 맨 위부터 조회 칸까지, 더치트 폰용은 PC 화면을 폰 폭에 맞게 자르고 선·꼬리표를 크게(더치트 모바일 화면은 자동 브라우저에서 열리지 않음).
- 사이트 화면이 바뀌면 다시 찍기: `SHARP_PATH=… PLAYWRIGHT_PATH=… node scripts/howto-shots.mjs`. 찍은 뒤 빨간 상자 위치를 눈으로 확인하고, 크기가 바뀌었으면 `public/app.js` 의 `HOWTO` size·sizeM 을 `sizes.json` 대로 맞출 것.
- 링크 정의는 `lib/links.mjs` 의 `guide` 표시, 화면 문구는 `public/app.js` 의 `HOWTO`.

## 개인정보 (기획서 8장)

- 원본(번호·사진·대화)은 분석이 끝나면 서버에서 버린다. 디스크에 쓰지 않는다.
- 리포트에서 넣은 정보를 다시 볼 수 있게(카드 제목 옆 '사진 보기'·'대화 보기' 등, 2026-10-26 오너) 화면이 결제 직후 원본을 **점검한 기기의 IndexedDB**(datecheck/inputs)에 리포트와 같은 24시간 둔다. 서버로는 다시 보내지 않는다. 리포트 아래 '이 기기에서 지우기'로 바로 지운다.
- 예시 리포트 `/report/example` = public/example-report.json(대화 43줄·번호 010-0000-0000 은 꾸민 자료, 사진은 사기에 자주 도용되는 유명인 사진의 예로 키아누 리브스 — 위키미디어 공용 CC BY-SA 4.0, Marybel Le Pape. 출처는 사진 창에 링크로, 안내 문구는 json note. 2026-10-26 오너가 연예인 사진으로 결정(초상권·퍼블리시티권 위험 안내 뒤)). 다시 만들 때는 C:/tmp/datecheck-test/full/capture.mjs → make-example.mjs.
- 리포트는 서버에 저장하지 않는다. 결과를 서버만 풀 수 있는 암호화 봉투(lib/token.mjs, AES-256-GCM)로 만들어 이용자 기기(localStorage)에 둔다. 결제 전 1시간·결제 후 24시간이 지나면 서버가 열어 주지 않고, 기기에서도 지운다. 그래서 리포트는 검증한 기기에서만 열린다.
- `data/` 에는 개인정보 없는 집계(퍼널·API 호출·파기 건수)와 삭제요청·문의, 관리자 접근 로그만 남는다.

## 화면 크기 대응

- 320·360·390·430(폰), 768(태블릿), 1024·1280·1440(노트북), 1920·2560(큰 화면)에서 점검했다.
- 폰: 메뉴 버튼, 입력 팝업 전체 화면, 버튼 세로 배치, 누르는 곳 40px 이상.
- 태블릿: 입력 팝업은 가운데 창(왼쪽 단계 목록 없이).
- 큰 화면(1800px~): 본문·설명 글자 한 단계 키움, 기관 이름 띠는 화면 폭에 맞춰 이어 붙임.
- 줄바꿈: 가운뎃점·숫자 하이픈은 묶고(런타임 밖 글자도 `glueText`), 끝줄에 낱말 하나만 남는 자리는 런타임이 피한다.
- 점검 결과(10가지 폭 × 첫 화면·메뉴·입력 13단계·리포트 2종·관리자·문의 창): 넘침·낱말 쪼개짐·끝줄 한 낱말·버튼 두 줄·작은 버튼·12px 미만 글자 모두 0건.

## Vercel 배포

- 구조: 화면 파일은 `public/` 을 그대로 내보내고, `/api/*` 는 `api/index.mjs` 함수 하나가 받는다(`vercel.json` rewrites, 최대 60초). 처리 코드는 PC 서버와 같은 `lib/app.mjs`.
- PC 서버 파일 이름을 `server.mjs` 로 두면 Vercel 이 서버로 잘못 잡으므로 `dev.mjs` 로 둔다.
- Vercel 프로젝트 설정 → Environment Variables 에 넣을 것: `GEMINI_API_KEY`, `GEMINI_MODEL`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `ADMIN_KEY`, `REPORT_SECRET`(긴 임의 문자열). 넣지 않으면 대화 항목은 '연동 준비 중'으로 나온다(규칙으로 대신 판별하지 않는다).
- 요청 크기 한도 4.5MB — 화면이 캡처를 긴 변 1600px 로 줄이고, 넘으면 미리 막는다.
- 집계·문의·관리자 로그는 Vercel 에서 임시 폴더(/tmp)에 쌓여 함수가 다시 시작되면 사라진다. 정식 운영 전에 Upstash Redis 같은 저장소 연결이 필요하다(관리자 화면에 표시됨).
